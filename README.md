# LoRA Stack Pack — кастомні ноди для ComfyUI

## Встановлення
1. Розпакуйте папку `comfyui_lora_stack_pack` у `ComfyUI/custom_nodes/`.
2. Перезапустіть ComfyUI і зробіть **hard refresh** браузера (Ctrl+F5).
3. Ноди зʼявляться в категорії `loaders/lora_stack`.

## Архітектура
- **LoRA Stack Container** — збирає налаштування 5 слотів (лора + ваги) у
  `LORA_STACK`, нічого не застосовує до моделі.
- **Load LoRA (StackInput)** — чистий хаб: `model`, `clip`, `lora_stack`.
  Застосовує все, що прийшло зі стеку.
- **Trigger Filter** — приймає 5 текстових списків тегів, ховає ті, що
  повторюються більше одного разу, віддає один відфільтрований список.

## 1) Load LoRA (StackInput) — `LoraStackInputLoader`
Тільки `model`, `clip`, опційний `lora_stack`. Жодного власного вибору лори.

## 2) LoRA Stack Container — `LoraStackContainer5`
У кожному слоті — 4 рядки, з порожнім рядком-розділювачем між блоками:
1. Стандартний компактний тумблер `slotN_enabled` (як у звичайних нодах
   ComfyUI — вузький, без кастомного малювання).
2. Кнопка **⚙ Slot N Info** — окремим рядком одразу під тумблером. Відкриває
   попап з повною інформацією (превʼю-картинка показується **тільки тут**,
   не на самій ноді).
3. `slotN_lora_name`.
4. `slotN_strength_model`.
5. `slotN_strength_clip`.

Вхід `lora_stack` (опційний) — для ланцюжка з іншим контейнером (більше 5 лор).
Вихід: `lora_stack` + 5 окремих `trigger_words_1` … `trigger_words_5`.

### Попап ⚙ Info
- Name, Base Model, Clip Skip, Resolution, Notes, Civitai-посилання, превʼю.
- **Тег-грід**: за замовчуванням топ-**200** тегів, відсортовані за
  кількістю тренувальних зображень — від більшої до меншої. Якщо тегів
  більше — зʼявляється кнопка **"Show all (N)"**, яка довантажує повний
  список без обрізки.
- Окреме поле **Trained Words** під тег-грідом — офіційний список
  тригер-слів із супутнього sidecar-файлу (якщо він є), незалежний
  від статистики тегів з датасету.
- **Notes** — авто-виявлене посилання на джерело завантаження (Civitai-сторінка
  або будь-яке інше `http(s)://` посилання, знайдене в метаданих файлу), плюс
  ваші власні нотатки: кнопка **✏ Edit** відкриває текстове поле, **Save**
  зберігає їх у маленький текстовий sidecar-файл поруч із LoRA — нотатки
  переживають перезапуск ComfyUI.
- **Copy Selected** / **Copy All** / **View raw metadata** / **Close**.

### Звідки береться картинка превʼю
1. Спершу шукається локальний файл поруч із LoRA: `<назва>.png/.jpg/.webp`
   або `<назва>.preview.png` тощо.
2. Якщо локального файлу немає — картинка береться з `images`-масиву у
   відповіді живого пошуку на Civitai (див. нижче).

### Trained Words та посилання на Civitai: як це працює насправді
**Важливо зрозуміти:** звичайний файл LoRA, натренований kohya_ss (як
переважна більшість LoRA), **не містить** усередині ні тригер-слів, ні
картинки, ні реального посилання на модель — тільки технічні параметри
тренування. Це не помилка нашого коду — це особливість формату
`.safetensors`. Ці дані можна отримати лише двома способами:

1. **Локальний sidecar-файл** поруч із LoRA (`<назва>.civitai.info`,
   `.civitai.info.json` або `.json`) — якщо LoRA-менеджер, яким ви
   користувались раніше, зберіг такий файл, ми його прочитаємо.
2. **Живий пошук на Civitai за хешем файлу** (якщо sidecar-файлу немає) —
   нода сама рахує SHA256 усього файлу LoRA та запитує офіційний публічний
   API: `https://civitai.com/api/v1/model-versions/by-hash/<hash>`. Якщо ця
   конкретна LoRA колись була завантажена на Civitai — API поверне її
   назву, базову модель, **Trained Words**, приклади зображень і правильне
   посилання на сторінку моделі. Результат автоматично кешується в
   `<назва>.civitai.info` поруч із файлом — наступного разу дані читаються
   миттєво й офлайн, без повторного запиту.

Це **повністю універсально** — працює для будь-якої LoRA, а не лише для
конкретного файлу, який ви завантажили, за умови що вона взагалі існує на
Civitai. Якщо LoRA тренована локально й ніколи не публікувалась на Civitai —
даних просто не буде ніде, це очікувано.

**Вимога:** машина, на якій запущено ComfyUI, повинна мати доступ до
інтернету (до `civitai.com`) для першого запиту по кожній LoRA; перший клік
на ⚙ по новій LoRA може зайняти кілька секунд (хешування файлу + мережевий
запит) — попап показує індикатор завантаження на цей час.

### Виправлено: помилкове посилання
Раніше поле "Source" в Notes іноді показувало
`https://github.com/Stability-AI/generative-models` — це посилання на
фреймворк тренування (`modelspec.implementation`), яке присутнє
**в кожній** SDXL LoRA й ніколи не вказує на саму модель. Тепер це поле
ігнорується, і посилання показується лише якщо це справжня сторінка Civitai
(знайдена через sidecar-файл або живий пошук за хешем).

### Звідки цифри біля тегів
Цифра — кількість тренувальних зображень, у підписі яких зустрічався цей
тег. Дані зберігає сам тренер (kohya_ss) у `ss_tag_frequency` прямо в
`.safetensors`. Список сортується за спаданням цієї цифри.

### Trained Words vs теги
- **Теги (тег-грід)** — статистика підписів датасету (`ss_tag_frequency`),
  завжди доступна, якщо тренер її зберіг.
- **Trained Words** — офіційний, курований творцем LoRA список тригер-слів
  (поле `trainedWords` у `.civitai.info`, який створюють Civitai-завантажувачі)
  — може бути відсутній, якщо такого супутнього файлу немає.

Виходи `trigger_words_1` … `trigger_words_5` ноди-контейнера віддають той
самий топ-200 список тегів (тег-грід), відсортований так само.

## 3) Trigger Filter — `LoraTriggerFilter`
До 5 текстових входів (`word_list_1` … `word_list_5`, підключаються дротами —
типово з `trigger_words_1..5` контейнера) → 1 вихід `filtered_words`. **Жоден
із 5 входів не є обов'язковим** — нода коректно працює навіть з одним
підключеним входом (решта просто вважаються порожніми).

**Логіка:** слово, що зустрічається (без урахування регістру) більш ніж в
одному з 5 списків, повністю ховається з результату. Лишаються тільки слова,
які трапились рівно один раз серед усіх пʼяти входів.

**Кнопка "⚙ Filter Settings"** відкриває попап із вибором сортування
результату:
- *За кількістю тренувальних зображень (як прийшло)* — зберігає порядок
  появи слів у вхідних списках. Оскільки кожен `trigger_words_N` вже
  відсортований контейнером від найчастіших тегів до найрідших, це є
  наближенням до сортування за кількістю зображень (справжні числа-лічильники
  в цю ноду не передаються — лише текст, тому це саме наближення за порядком).
- *Алфавітний порядок* — A→Z.

## Типові графи

Один контейнер + застосування:
```
CheckpointLoader ──▶ model, clip ──────────────────────┐
                                                         ▼
LoRA Stack Container ──▶ lora_stack ──▶ Load LoRA (StackInput) ──▶ (MODEL, CLIP)
```

Фільтрація тригер-слів перед використанням у промпті:
```
LoRA Stack Container ──▶ trigger_words_1..5 ──▶ Trigger Filter ──▶ filtered_words ──▶ (текстова нода промпту)
```

Більше 5 лор — ланцюжок з двох (і більше) контейнерів:
```
LoRA Stack Container #1 ──▶ lora_stack ──▶ LoRA Stack Container #2 ──▶ lora_stack ──┐
                                                                                       ▼
CheckpointLoader ──▶ model, clip ────────────────────────────────────▶ Load LoRA (StackInput) ──▶ (MODEL, CLIP)
```

## Попап: адаптивність та керування
- Попап адаптується до розміру екрана: на вузьких/невисоких вікнах він
  повністю скролиться як єдине ціле (виправлено баг, через який блок тегів
  стискався в тонку смужку на малих екранах).
- Закривається клавішею **Esc**, кліком поза вікном, або кнопкою **Close**.
- Прев'ю-картинка показується **тільки всередині** попапу ⚙ Info — на самій
  ноді контейнера картинки більше немає.
